# Story brief from the reporting file: tried on its invented example

- **Product:** Claude, run in Claude Code
- **Model:** Claude Sonnet 5.5 (model ID claude-sonnet-5-5)
- **Date:** 2026-11-10

The inputs were the invented example in [example.md](example.md): the request, the publication profile, the reporting file, the two source documents and the prior coverage index for the invented Tallowby Courier. No client data was used.

This is the third run on the example, and the record replaces the earlier ones. The first run, earlier the same day, was made by an assistant that had not written the template; an independent review then found faults and the template was revised, and a second run followed those revisions. A second independent review passed the template with minor points, and the template was revised again (see below). This run was made by the assistant that made the latest revisions, following the revised instruction block and output format against the example's inputs, with the example changed only where the review required it (two lines of the brief: G1 and P1). It had read the earlier runs and both reviews, so it is not an independent run, and its brief is the one published in the example.

## What was observed

The brief was produced in full. Every heading in the output format printed, each with entries, and the closing line was used. No stop condition applied: the headers on both tables matched, every source type was on the list, the file had 8 notes against a limit of 60, there were 3 assertions against a limit of 3, and every index entry had a summary. The assistant verified nothing, searched nothing and contacted no one. The brief now prints the "Not a claim" line for N8 as the output format provides. Counts were checked by hand against the lists: 11 claims (2 Confirmed in the file, 4 Single-source, 1 Unverified, 4 Conflicting), 8 gaps (2 Conflict, 1 Primary source unavailable, 1 Unverified, 4 Single-source), 6 questions, 7 items to settle. Every gap ends with a question.

What the earlier runs and reviews found, and what was done:

- **Gaps that were not questions.** In the published example two gaps were statements. The template now says every gap ends with a question, in the procedure, the output format and the instruction block, and the example's G7 and G8 end with one.
- **A claim beyond the inputs.** The first example listed the contractor as having stopped work. Note N3 names no one who stopped the work. That entry is removed; C5 appears in no list of claims about a party's conduct.
- **Instruction block shorter than the procedure.** The block now carries the default rule and how to print it, the claim limit and its stop, the definition of Primary source unavailable (including a note that quotes an unsupplied document), the blank-summary rule, the named source who asks not to be identified, and the instruction to tell the person to remove private details. It was re-read against the output format line by line.
- **Splitting a note, the number of gaps, "named people or organisations", "needs", seasons and the number of "Worked out" lines** were ambiguities in the first run. The template now states a rule for each: cut at each sentence and at each separate assertion inside one; one gap for each instance, grouped by type; claims about a party's own conduct; the claims that state the assertion's parts as worded; no "Worked out" line for seasons; one such line for each comparison. This run followed them, and they produce the same claim count and gap count as the first run's own brief.
- **Minor points from the second review.** Applied to the template and, where the brief was affected, to this run: the instruction block now lists the seven parts of the pitch for the unanswered questions and says a part wholly covered by other parts is not repeated (here, "what happened" is covered by Q1 and Q2, so the six questions stand); the block now carries the rule that gaps touching a central assertion come first within each type; the output format and block now provide the optional "Not a claim" line; the split rule now says a clause that only places an event in sequence stays with it (C5's "after the ground tests failed") and a clause giving the purpose of a figure or change is cut (C8); P1 now agrees with C1 and only touches C2, because the index summary says opening and C2 says completion; G1 now says Source B is anonymous without recorded approval, since C6 is Conflicting and so gets no Unverified gap. The version notes and profile now say the record is of a run made by the revising assistant.
- **A figure with no year** (C7 against C9). The template now says to compare it as if for the same period and to list that reading under To settle; this run did so.

Where this run still had to use judgment:

1. **"Cannot be judged alone."** The split rule now separates a clause of sequence from a clause of purpose, but whether a given clause is one or the other can still be a matter of reading. "to cover the depot" was cut from the levy rise as a purpose; "after the ground tests failed" was kept with C5 as sequence; another reader might read either differently.
2. **Which claims an assertion's parts are.** For A3 the parts are the levy figure and its link to the depot; "overrun" has no claim, which is stated in words. The choice of C7, C8 and C9 is a reading.
3. **A claim that implies a party without naming one.** C7 and C8 imply the council raised the levy. Under the rule they are not listed, and the choice is put to the editor under To settle.
4. **Which claims the records request bears on.** N8 says only "revised programme"; the gap ties it to C3, and To settle asks about C4 and C6.
5. **The "For" line.** The format uses the person who ran it; the example gives the coordinator's title as supplied.

Shortcomings: this run was not independent, so it shows that the revised block can be followed to this brief and that the brief meets the revised output format, not that a separate assistant would produce the same one. The earlier independent run no longer stands as the record of the current wording. Nothing here shows how the template behaves on a real file, a larger file or a different publication's rule. No stop condition or refusal has been run, and the acceptance tests in the template are still unrun; an independent re-run on the current wording has not been made.
